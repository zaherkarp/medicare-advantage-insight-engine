# Targeted archive repair

The contextual SCAN fix changes future scoring. It does not guarantee that an
existing story's entities, score, explanation and saved review draft agree.
Legacy `ma-signal-backfill --rescore` only rescales rows whose categories change
and does not rebuild all derived fields. Keep that workflow unchanged; use this
separate tool for a reviewed, explicit set of existing IDs.

This command is not wired into ingest or deployment. Merging it performs no
archive repair. Production application and site regeneration require a separate
operator decision and access to the private restored archive.

## Plan without database writes

Run from the exact reviewed checkout with the deployment's effective scoring
configuration and required environment settings. The maintenance config loader
skips discovered-feed loading, which otherwise initializes the archive. This
does not change scoring inputs or the normal config-loading default.

```bash
python -m ma_signal_monitor.archive_repair plan \
  --root /path/to/repository --db /private/state.db \
  --item-id STORY_ID --plan /private/repair-plan.json
```

Repeat `--item-id` for each target, up to 100. Empty, duplicate and missing IDs
are errors. There is no all-archive mode. SQLite opens with `mode=ro` and
`query_only`; no StateStore constructor, migration, FTS initialization, network
fetch or source rewrite runs. The output plan is created exclusively with owner
read/write permissions and never overwrites another file.

Review each before/after value, including intentionally removed drafts, and the
reported canonical SHA-256. The plan preserves original derived values as
rollback evidence. It contains archive-derived text: keep it private and outside
the repository, published site and public workflow artifacts. The hash detects
changes to a reviewed plan; it is not authentication or a substitute for review.

## Apply the reviewed plan

```bash
python -m ma_signal_monitor.archive_repair apply \
  --root /path/to/repository --db /private/state.db \
  --plan /private/repair-plan.json --expected-sha REVIEWED_SHA256
```

Application requires the same derivation code and effective configuration. It
locks the existing database with `BEGIN IMMEDIATE`, validates every selected
row and recomputes every proposed result before writing. A stale source,
identity, deduplication pointer or derived value rejects the batch. Drafting
errors abort rather than silently removing a draft. A write failure rolls back
the entire transaction. Retrying an already-applied plan changes zero rows.

Only these fields may change: score, primary and secondary categories, entities,
states, review draft, scoring explanation, threshold at scoring, eligibility
tier and eligibility reason. Source text, links, source priority, original dates,
IDs, duplicate pointers, feedback, FTS contents and historical digests remain
untouched. Fields are rebuilt even when categories have not changed. Source
priority zero and unknown publication dates are preserved. Missing/invalid fetch
dates, incomplete schemas and unsupported source inputs fail closed.

The current production derivation paths do not consume source tags, source type
or author, which the archive does not retain. Reconstruction uses inert values
for those fields. If a future scorer starts using them, this contract must be
revisited rather than inventing tags from today's source configuration.

## Guarded rollback

```bash
python -m ma_signal_monitor.archive_repair rollback \
  --db /private/state.db --plan /private/repair-plan.json \
  --expected-sha REVIEWED_SHA256
```

Rollback restores only the recorded derived before-images. It requires unchanged
source/identity fields and the expected post-image, so it cannot silently undo a
later edit. Already-restored rows are no-ops. It uses the same atomic transaction
and never rewrites other tables. Retain the plan until the repair is verified
and its rollback window is closed; losing it loses these before-images.

## Verify the reader's outcome

After an authorized apply, inspect the changed rows and regenerate the relevant
site views through the established pipeline. Confirm the exact deployed SHA and
actual story and Angles outputs. A removed SCAN false match should no longer
connect an unrelated vendor to a payer lawsuit; a suppressed draft must be gone
from the story page while the archived source remains available. Historical
digest snapshots are intentionally not regenerated by this command. This tool
does not fix broad briefing eligibility, decide newsworthiness, validate causal
claims, approve LinkedIn text or publish anything.

Tests use synthetic databases to prove byte-unchanged planning, explicit scope,
stale-plan rejection, atomic failure, idempotence, guarded rollback, preservation
of unrelated records and rendered Angles/story changes. They are not a replay
of the private production archive and do not establish a completed live repair.
